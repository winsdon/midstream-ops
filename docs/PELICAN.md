# 分组鹈鹕测试

管理端入口为 `/pelican`，客户菜单 URL 为 `https://你的监控站/embed/pelican`。
客户入口沿用现有 `plaza.enabled`、`plaza.sub2api_base_url`、`plaza.sub2api_jwt_secret` 设置及用户会话；无需另一套登录配置。

## 首次配置

1. 在 sub2api 准备可直接调用的上游账号（`api_key` 类型、`active`、配好 `base_url`），并把这些账号挂到要用作作品归属的分组上（`account_groups`），或在手填模式里自备网关地址与 Key。
2. 在管理端「鹈鹕测试」页面点作品列表右上角的**发起测试**，在弹窗里依次选择：
   - **归属分组**：作品挂到哪个分组下。客户页按分组筛选已发布作品，发布范围也按分组计算；分组不再决定凭据来源。
   - **凭据来源**：
     - **本站账号**：选项按上面的归属分组过滤，列出挂在**该分组**下、且平台匹配的 `api_key` 账号（归属看 `account_groups` 关联 + 平台匹配，`composite` 分组接受全部平台；不看账号状态与调度开关，因为本页是拿账号自己的地址与 Key 直连上游）。每个账号右侧显示 sub2api 当前状态徽章，口径与 sub2api 后台账号列表一致：限流中 > 过载 > 错误 > 临时不可调度 > 停用 > 不可调度 > 正常，限流 / 过载 / 临时不可调度附恢复时间，错误信息悬停可见；停用、错误等账号也能勾选测试；支持多选与搜索，勾几个账号就生成几件作品，一次最多 100 个（与后端单批次上限一致）。后端用各账号自己的 `base_url` 与 Key 直连上游；列表只返回名称、平台、地址与所属分组，Key 不出后端。
     - **手填地址 + Key**：自己填网关地址（可带 `/v1`，不要填具体生成接口路径）与 Key，直连该地址；每次一个目标。
   - **模型**：从归属分组的可用模型里选，或直接手填；多选账号共用这一个模型。
   - **接口协议**：账号来源按账号平台自动适配（anthropic → Messages，openai → Responses / Chat Completions，混选时勾选值只作用于 OpenAI 账号）；手填来源三种都可选。
3. 确认提示词后发起测试：一次提交把所有勾选的账号作为一个批次。**思考强度**（默认 medium）、**禁止思考**（默认勾选）与**同时测糖果题**（默认勾选）在弹窗里常显；并发数、输出上限、单项超时收在「高级选项」里。主页面只展示作品列表（作品墙），新提交的一批会在墙上按状态自动刷新。
4. 预览作品，勾选后发布。客户可查看所有普通分组的已发布作品；专属、停用或已删除分组不展示。

手填来源的 Key 明文既不出现在任何接口响应里，也不写入任务表或结果表：落库的是 sha256 指纹，明文只在进程内用于发请求，因此**重新测试需要再填一次 Key**。同一批次内账号来源的 Key 也在批次开始时快照到内存。

## 执行与历史

- Claude 使用 Anthropic Messages；GPT 默认 OpenAI Responses，也可选择 Chat Completions。协议与账号平台必须匹配，不匹配的目标在提交时即被拒。
- 默认并发 3、每项超时 900 秒、输出上限 32,000 tokens；高级选项可调整。
- `GET /accounts` 的每个账号带 `group_ids`（按 `account_groups` 与平台匹配算出的归属分组），管理端据此按分组过滤账号选择项；另带 `state`（`active / inactive / error / rate_limited / overloaded / temp_unschedulable / unschedulable`）、`state_until` 与 `error_message`；结果记录带 `account_name`（发起测试时的账号名称快照，只出现在管理端接口里，客户接口不下发）。
- 默认提示词（不分协议）：`独立画一个中国传统水墨风格的鹈鹕骑脚踏车html，你不需要任何测试，完全重新制作，不要看任何项目，从0开始`（由 Simon Willison 的 pelican-on-a-bicycle 改写，原为模型检测「智商测试」的鹈鹕题）。新测试的提示词默认已带「禁止思考」后缀；实际使用的提示词随记录留痕。
- Messages 请求与模型检测共用一套 thinking 口径（`modeldetect.ThinkingParamFor`）：adaptive 型号发 `{"type":"adaptive"}`，旧型号带 `budget_tokens`，型号不认识或本来不支持 thinking（如 Haiku 3.5）时不发；Messages 同时复用同一套 `claude-cli` User-Agent。Opus / Sonnet 5 起不传也会思考且关不掉，思考量与正文共用 `max_tokens` 上限，输出上限给小了会在写完前被截断。
- **思考强度**（默认 medium；可选 low / medium / high / xhigh / max）只对 Messages 生效，按 `output_config.effort` 发送（`modeldetect.EffortFor`）：只发给 adaptive 型号，旧型号、Haiku 4.5、不认识的型号不发；Opus / Sonnet 4.6 没有 xhigh，按 high 发送。GPT 协议忽略该选项。强度随记录留痕（详情参数行 `effort=`），「重新测试」沿用原强度；该字段出现之前的旧记录与旧提交视为未指定（不发，上游默认）。强度越高耗时越长，注意单项超时。
- **禁止思考（提示词引导）**（默认勾选）不是请求参数：勾选后只在提示词末尾追加固定后缀 `直接输出完整 HTML，不要思考，不要解释。`，提示词本身随记录留痕，「重新测试」沿用；只作用于鹈鹕作品，不影响糖果题。实测 Claude Opus 5.5（thinking adaptive + effort low）同一道 HTML 作品题：加后缀前思考 6,785 / 12,315 token、耗时 333.7s / 389.8s；加后缀后思考 0、耗时 186.8s / 184.9s，作品仍完整。**注意**：这是模型层的引导而非 API 关闭——`thinking.type=disabled` 会被上游拒绝，省略 thinking 也会默认思考；复杂推理题上可能仍思考，也可能因“不要思考”掉质量，重要题目建议复测确认。「恢复默认提示词」保留当前勾选状态。
- 管理员填写的提示词作为用户消息原样发送；另附统一交付指令，要求在回复正文中直接返回完整独立 HTML，不依赖外部资源，不用文件路径或“已创建文件”的说明代替代码。Messages 使用 `system`，Responses 使用 `instructions`，Chat Completions 使用 system 消息。完整请求（含交付指令，不含 Key）保存在结果详情的请求参数中。不提供文件写入或工作区工具。
- Responses 流优先读取 `response.completed` 中的最终正文；完成事件没有正文时才使用累计文本增量，避免只收到前言增量而漏掉最终 HTML。
- 流式响应必须正常结束；截断、异常断流、无完整 HTML/SVG 都不允许发布。可在详情查看已收到的原始回复。
- 提交请求使用幂等 ID：账号来源的参数没改动时，待确认的「重试提交」会把上次那份目标原样重放，沿用同一个请求标识，不会重复执行；改了任何参数则算新测试。待确认提交写 sessionStorage 前会剥掉手填 Key，刷新后必须重填：Key 与上次一致才判为同一次提交，不一致会撞上已用过的请求标识并报冲突，先「清除待确认提交」再发起。超过 100 个目标（或目标重复、参数非法）后端整单拒绝。
- 「重新测试」创建新批次和新结果，并关联原记录。账号来源可换一个账号重跑，手填来源需重新填 Key。它不会覆盖旧作品，也不会自动换协议或自动重发付费请求。改造前用「专用测试用户分组 Key」生成的旧记录不支持重新测试，仍可查看、撤下与删除。
- 取消会停止排队和正在读取的请求，但无法保证网关撤销已产生的用量。服务重启把遗留等待/运行任务标记为中断：进程内的凭据快照同时失效，不自动恢复调用。
- 发布与撤下支持批量且在同一事务中完成；删除仅允许非运行、未发布结果（已发布的先撤下）。卡片与详情都提供单条删除，未发布记录也可勾选后批量删除。
- 管理端作品卡片与详情显示**所属账号**（账号来源取记录里的名称快照，账号改名或删除后仍显示当时的名字；手填来源显示网关地址），客户嵌入页不展示账号名。
- 客户「最新作品」按分组、模型及实际测试时间选取最新已发布记录。日期筛选使用浏览器本地日期并转为 UTC 查询，页面显示时区。发布时间不改变测试顺序。
- 作品保留原始代码，不修补画面、不自动评估画质、不生成排名。历史默认长期保留。

## 糖果题

勾选「同时测糖果题」（默认勾选）后，每个目标在画鹈鹕的同时**并行**再发一道最坏情况推理题（同一账号、同一协议、同一思考强度，共用单项超时）。糖果题请求不带交付指令、不加禁止思考后缀，`max_tokens=16000`。

- **判定与展示**：结果写进记录 metadata 的 `candy`（`queued / correct / wrong / no_answer / failed`，含 `answer`、`expected`、`duration_ms`、`error`），列表接口直接带出；回复全文（截断 2 万字）存 `output.candy_text`，管理端详情「糖果题回复」页签查看。作品卡片显示糖果题徽章（答对 / 答错与标准答案 / 未给出答案 / 失败），**客户嵌入页同样可见**，客户接口只下发 `status / answer / expected`。
- **与作品互不影响**：记录状态、发布资格只看作品；作品失败照样保留糖果题结论，糖果题失败也不影响作品。取消或重启中断时仍为 `queued` 的糖果题在界面上显示「未完成」。
- **兼容**：请求体 `candy` 字段 `omitempty`，没勾时与旧请求逐字节一致，幂等 hash 不变；「重新测试」沿用原记录是否测了糖果题。旧记录没有 `candy`，卡片不显示徽章。

**题目与标准答案**：标准答案 **21**。关键在题干那句「不同的形状靠手感可以分辨」：口味摸不出来、形状摸得出来，所以摸的人可以自己定圆的摸几颗、五角星摸几颗。设圆的摸 x 颗、五角星摸 y 颗，要保证凑成「圆苹果 + 星桃子」或「圆桃子 + 星苹果」，就得同时排除四种凑不成的局面：

- 圆的全是西瓜（x ≤ 8 时可能）→ 需 x ≥ 9；
- 五角星全是西瓜（y ≤ 4）→ 需 y ≥ 5；
- 手里完全没有苹果（x ≤ 9+8=17 且 y ≤ 6+4=10）→ 需 x ≥ 18 或 y ≥ 11；
- 手里完全没有桃子（x ≤ 7+8=15 且 y ≤ 7+4=11）→ 需 x ≥ 16 或 y ≥ 12。

最省的是五角星 12 颗 + 圆的 9 颗 = 21 颗。把形状当成摸不出来、只按总数做最坏情况，会得到 29 —— 这正是这道题要筛掉的漏读题干的答案。标准答案由 `TestCandyAnswerMatchesPuzzle` 按题目数据穷举验证，不靠手算。

**判分**（`service/pelican_candy.go`）：题目末尾要求「请在回答最后单独一行按「最终答案：数字」的格式给出答案」—— 只规定格式、不含提示。判分先剥掉 `**` `` ` `` `$` 这类包裹记号，取最后一次出现的格式行；模型没照做时，才在**末尾 5 行**里兜底认 `\boxed{N}` 与「答案是 N」。数字后紧跟运算符的不算（「答案是 12+9=21」里的 12 是算式的一部分）。回复没正常结束（被 `max_tokens` 截断或断流）时只认恰好落在最后一行的格式行，推理里出现过的中间数一律不算；取不到答案即记失败并保留原因。

## 作品抽取

抽取逻辑（`modeldetect.ExtractArtwork`）移植自 cockpit-tools：优先 `html/svg/xml/无语言` 代码块，有多份完整作品时取带动画的（模型常先给静态版再给动画版），最后一个代码块没闭合、前面又没有完整作品就宁可不取；没闭合的 `<html>` 只是说明文字，继续找独立 SVG；只截取、不修补。

## 预览

作品渲染在 1280×800 的虚拟视口里，再整体等比缩放到卡片或详情框内：固定像素尺寸的 HTML 也能整幅看到，且作品自己的滚动条被关掉。因此内容高于 800px 的页面在预览里会被裁切（详情提供「源码」页签查看原文），依赖外部 CDN 的作品也可能显示不完整。动画在不具备同源权限的 iframe 中自动播放；进入视口加载、离开销毁，禁止外部脚本与资源加载。管理员应预览后再决定发布。

作品是不可信内容，只放进**不带** `allow-same-origin` 的沙箱 iframe —— 不透明源，拿不到本站 localStorage 里的登录 token，也碰不到父页面。srcdoc 最前面是 CSP（`default-src 'none'`，只放行内联脚本 / 样式与 `data:` 资源，`connect-src` 等一律 `'none'`），挡住追踪像素、`fetch` 回传之类的子资源外连；作品脚本运行前另有一段脚本把 WebRTC 构造器锁死（CSP 管不到它）。缩略图不接收鼠标，点击由外层接住去开详情。

## 接口

管理员鉴权前缀 `/api/v1/pelican`：

- `GET /accounts`（可选账号，不含密钥，含 `group_ids` 归属分组）、`GET /groups`（可选归属分组与模型提示）
- `POST /batches`、`GET /batches/:id`、`POST /batches/:id/cancel`
- `GET /results`、`GET /results/:id`、`POST /results/:id/retry`
- `POST /results/actions/publish|unpublish|delete`，请求体 `{ "ids": [1, 2] }`

测试目标提交格式：`{ "group_id": 1, "source": "account" | "manual", "account_id": 7, "base_url": "https://api.example.com", "api_key": "...", "model": "...", "protocol": "messages" }`（`account_id` 与 `base_url`/`api_key` 按来源二选一）。`POST /results/:id/retry` 请求体 `{ "request_id": "...", "account_id": 7, "api_key": "..." }`：账号来源可省略 `account_id`（沿用原记录），手填来源必须带 `api_key`，旧记录返回 `pelican.errors.legacyRetry`。

嵌入会话前缀 `/api/v1/embed/pelican`：

- `POST /session`：交换 sub2api 用户 token。
- `GET /filters`、`GET /results`、`GET /results/:id`：需嵌入会话。

列表参数：`group_id`、`model`、`from`、`to`、`page`、`page_size`；日期为 RFC3339，`to` 为不含边界。客户默认最新模式，`history=true` 查询全部历史。管理员另支持 `batch_id`。列表不包含作品代码；详情按权限单独读取。

## 部署与验证

部署包含前端构建的新版本并重启后端；启动自动执行 monitor 库的 `009_pelican.sql` 迁移（本改造不新增迁移，`metadata` 为 JSONB）。任务执行器按本项目的单实例部署方式运行，不支持多个服务实例共享任务表并同时执行启动恢复。

验证命令：

```sh
cd backend
go test ./...
cd ../frontend
pnpm typecheck
pnpm test
pnpm build
```

涉及 PostgreSQL 的测试要求 `MONITOR_TEST_PG_DSN` 指向独立测试库；测试会创建临时 schema、执行迁移并清理。未设置时明确跳过。网关测试全部使用本地模拟响应，不调用真实付费模型。

请求交付方式参考 [cockpit-tools 的鹈鹕请求实现](https://github.com/jlcodes99/cockpit-tools/blob/4ea6a34df6aa3b2d494c3cca5983bd09a84a9e3a/src-tauri/src/modules/codex_pelican_transport.rs#L310)。本站按目标来源解析凭据后直连上游端点，不使用该项目的 Codex 账号登录与客户端身份机制，也不经由本站网关转发。
